# 产物目录

开始时固定目标项目根目录 PROJECT、产品书目录 BOOK、分析目录 ANALYSIS 和本次工作目录 WORK，后续命令使用它们的绝对路径。CLI 的省略路径是当前工作目录，不会自动选择本约定；不要依赖当前目录或每个阶段重新选择位置。

## 新建与已有文档

- 首次初始化且用户没有指定位置时，BOOK 固定为 `PROJECT/.blueprint/`；即使根目录没有示例，也不在根目录创建产品 JSON 或 HTML。不另起产品名目录、`blueprint/`、`init-preview/` 或多个候选产品书。
- 用户指定位置时遵循指定位置。已有目标产品书使用其原路径；维护和实现先定位同一份文档，不为了套用新默认值另建、复制或搬迁。根目录其他产品的示例保持原样。
- `.blueprint/` 已占用而目标不明确时先识别已有内容；已有目标转维护，不能自动加数字后缀来绕过冲突。只有影响目标选择的真实冲突才询问。

## 存放约定

项目根目录 `.blueprint-workflow.json` 是用户可维护的工作流配置，不是中间产物。先确定配置再扫描；没有明确调整要求时不改写它。独立 discover 仅保存分析目录，不创建 BOOK。

| 产物                                                   | 位置与处理                                                                                              |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------- |
| 产品定义、独立 HTML、最终交付审阅                      | `BOOK/product-document.json`、`BOOK/index.html`、`BOOK/delivery-review.json`                            |
| 分析会话、读取凭据、流程映射、验收记录与工具日志       | `PROJECT/.blueprint-analysis/`，使用 CLI 返回的实际路径；不复制、改名或搬动会话                         |
| AI 组装的扫描配置、变更批次、trace、方案输入及辅助脚本 | `PROJECT/.blueprint-analysis/work/本次任务唯一编号/`；一次确定 WORK，后续复用；简单输入优先 `--input -` |
| 临时运行副本、截图、安装包及下载文件                   | 宿主系统临时目录；运行副本和探针由工具管理                                                              |

`analysis scan` 的目标始终是 PROJECT，不是 BOOK 或 WORK。相关项目源码和文档仍按实际范围读取；生成文件不作为源码、业务上下文或新的实现依据。

不要把批次 JSON、分析脚本、测试夹具、日志、审计 Markdown 或安装包散放在根目录、源码目录和 BOOK。临时验收夹具通过工具的 `fixtures` 在副本内新增；初始化不向原项目写入测试代码。实现流程中正式交付的业务代码和必要测试遵循目标项目自身目录约定。

## 恢复与结束

- 保存 WORK 与 CLI 返回的会话路径，恢复时复用，不创建一批平行目录。
- 成功后清理本任务创建且不再需要的工作文件；失败或中断时保留可恢复进度。保留工具管理的分析会话、执行记录和日志，不将证据当作临时文件删除，不清理其他任务内容。
- 用户明确要求重新初始化时，先保护已有定义、批注、历史及证据；需要备份时放在 `PROJECT/.blueprint-analysis/backups/本次任务唯一编号/`，保留原会话路径。普通初始化不自动创建备份或重建已有产品书。
- 交付前清点本任务新增文件：产品书只有约定的交付文件，其余产物在上述目录；发现本任务放错的可移动工作文件时先纠正，再启动或复用指向 BOOK 的编辑服务。已绑定绝对路径的文档和证据不能仅靠移动来整理。

交付检查会对照当前扫描清单报告之后新增、位于约定目录之外的文件，并检查 `.blueprint/` 内杂项；这些问题不能用 acknowledgedGaps 当作能力限制豁免。扫描前已存在的文件不自动归因本任务，不通过重扫掩盖本任务杂项。普通 verification run 也在临时副本运行；副本不是操作系统沙箱，命令仍需遵守目标项目与外部资源的授权。遇到调试失败时使用 WORK 和工具副本，不直接在原项目根目录试写测试文档。

分析会话整体保留。新格式的 state.json 是小型索引描述，state.sqlite 保存索引与记录；旧 JSON/日志格式继续兼容。不要只复制或手工改写其中一个文件。
