# 初始化产品书

将项目的产品定位、功能、规则和流程整理为人与 AI 共享的产品书，保存产品 JSON 并生成独立 HTML。初始化包含核验已有功能，不包含开发新功能。

本流程中的 CLI 操作由 AI 在授权范围内直接执行，交付页面链接和处理结果，不要求用户复制命令或打开终端代为操作。遇到工具、环境或权限阻碍时先排查，无法解决时说明具体阻碍及需要的授权，不把执行任务转交用户。用户主动询问命令用法时再提供命令。

## 工作流程

1. 确定目标项目与输出目录，读取项目介绍及配置。保留其他产品的示例；同一任务恢复时先按“完成与恢复”核对进度，其他已有目标蓝图先检查源码状态并转为维护，不覆盖重建。
2. 按 [初始化流程](references/workflow.md) 建立分析会话，完整读取约定范围内的源码和上下文，记录实际行为与需求来源。支持范围先查询 analysis capabilities；读取语言工具和上下文边界，不虚构深度覆盖。
3. 从核心用户旅程归纳独立业务能力。建模时读 [内容审阅](references/content-review.md)，整理图表时读 [图表说明](references/diagrams.md)，保存有依据的定义、流程及适用图表。
4. 按 [验收与交付检查](references/verification.md) 逐功能核验。已有实现与当前定义一致且实际检查通过时登记完成；新需求、未实现或无法核验的功能保留草稿，并在产品书里写明具体原因。
5. 完成严格或明确的部分交付检查后自动启动本机 `serve`，打开可编辑、可保存的产品书，按下述格式交付。用户明确只要预览时停在预览；正常首次初始化直接保存，不等待用户确认陌生项目的内容。

选择验收范围和执行方式时读取 [分层验收](references/layered-verification.md)，先保存逐业务步骤方案，再执行组件、契约或必要的端到端验证。源码完整分析与全系统联调分开；选择端到端验证时再读取 [业务流程核验](references/flow-verification.md)。漏读、漏记录和未执行的声明场景继续补齐，只有真实限制才允许明确部分交付。

## 必须保留的边界

- 函数是源码阅读单位，功能按独立用户目标、结果和权限边界划分；总旅程不代替独立功能。
- 区分已有行为、需求、推断与未知。扫描和结构检查不证明业务理解正确，也不代替真实验收。
- 保留用户原文、稳定编号和历史；使用 CLI 的哈希与版本保护写入。只维护业务数据，不改固定页面模板。
- 完整读取后仍须逐项解释函数的 reviewPoints；记录数量齐全不代表分析合格，恢复旧记录先运行当前检查。未读完或未分析完属于待完成工作，保存中间文件不能宣称初始化完成。

## 交付给用户

检查通过后，按 [验收参考中的“启动可编辑页面”](references/verification.md) 用持久任务运行 `serve /文档目录 --port 0 --json`，确认服务连接到本次产品文档且支持保存，再用宿主的浏览器或页面打开能力打开实际返回的网址。提供服务网址，不以直接打开 HTML 文件代替可编辑入口。

服务已可访问但无法自动打开浏览器时，仍交付该网址并简短说明。服务启动或保存能力检查失败时明确说明编辑入口尚不可用；静态 HTML 只能作为标明“只读”的备用链接，不能称为可编辑交付。

验收、交付检查、服务启动和保存能力核对都由 AI 实际完成，结果留在产品书及内部记录中；不把这些工作变成给用户的技术报告或待办清单。

成功回复直接采用以下版式，替换占位内容，不添加其他总结章节：

```markdown
[打开产品书（可编辑、可保存）]({{已验证的服务网址}})

产品定位与核心业务旅程

{{目标用户与产品作用的简短说明}}

核心流程：{{该产品的核心工作流}}

- {{旅程名称}}：{{用户目标与结果}}
```

链接使用服务实际返回并已验证的网址。旅程按实际项目展开，不固定数量或照搬本工具的旅程。最终回复前核对是否符合此版式，删去“结果／做了什么／如何验证／产物与需要你决定的事”等技术汇报，以及检查结论、哈希、执行编号、后台任务编号、文件清单和逐功能状态表；用户主动要求时再提供。

不主动要求用户决定是否提交 Git、修改忽略规则、固定端口或长期托管，这些不是初始化的交付条件。确有无法自行解决且阻碍用户使用的问题时，用一句话说明实际影响与所需决定，不以长篇报告代替处理，也不把失败宣称为成功。

## 完成与恢复

本流程按一次初始化任务完成，不主动安排额外执行轮次。产品书检查通过、编辑入口就绪后结束；若宿主已跟踪本次初始化目标，先同步其完成状态，再发送最终回复，并保留编辑服务运行。

收到恢复或自动续跑通知时，先按验收参考核对现有交付。已完成且仍有效时只结束对应目标，不重建产品书、重复登记或重跑验收。需要回复时仍遵守上面的简短交付格式，不另起技术总结，也不追加本次任务以外的待办。
