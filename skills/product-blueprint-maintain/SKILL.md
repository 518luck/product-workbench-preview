# 维护产品蓝图

使用 `product-blueprint` CLI 0.2.1+；读 [references/workflow.md](references/workflow.md) 处理需求差异和版本。以 `--help`、`schema --analysis`、`schema --changes` 获取共享协议，不能改写固定模板来承载业务。

先读取用户定义和既有蓝图，再核验分析会话。相同快照继续 pending 单元；源码或解析配置变动后重新扫描，旧凭据不能复用到新快照。逐单元完整读取并分析，配置和测试另按用途归类。长函数需读完所有分段，嵌套函数仍有独立分析结果；完整读取不等于正确理解。

保留编号、分组、备注、验收历史和用户原文。扫描未发现某项不意味着删除。普通分析用 feature.update；改写原文只能在用户明确要求修改定义时用 feature.define。将业务影响范围明确写入 affectedFeatureIds，不根据自然语言猜测后让 CLI 自动处理。

区分代码已有行为、用户期望、推断和未知；步骤、规则、异常分别绑定有效源码分析或需求原文。未知不变成已确认事实，也不能支持完成登记。没有足够证据时交付有缺口的草稿，先说明缺口并得到草稿范围确认，才启用 `--allow-partial-analysis`。

运行 analysis check，预览具体变更，用户确认后提交同一批次。业务变化回到草稿；名称和分组只改变编辑版本。维护工作流不登记新版本完成；需要实现时转入明确授权的实现工作流。
