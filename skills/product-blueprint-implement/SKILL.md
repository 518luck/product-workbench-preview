# 实现与验收

在用户授权的项目与功能范围内，将蓝图中的明确需求落实到代码，核验实际行为并同步产品书。已有代码符合需求时核验即可，不重复开发。

本流程中的 CLI 操作由 AI 在授权范围内直接执行，交付页面链接和处理结果，不要求用户复制命令或打开终端代为操作。遇到工具、环境或权限阻碍时先排查，无法解决时说明具体阻碍及需要的授权，不把执行任务转交用户。用户主动询问命令用法时再提供命令。

## 工作流程

1. 运行 `document status`，读取蓝图及相关依赖。检查所有授权功能的定义、已保存批注和源码变化，不只筛选草稿。用户无须逐条复制批注或手动列出功能编号。
2. 按 [实现流程](references/workflow.md) 将批注、当前定义与实际代码对照，确定本次目标。需求明确且已授权时整理定义并直接实现；有歧义、冲突或需要扩大范围时先确认，保留相应批注。
3. 遵循目标项目自身约定修改代码。源码已实现且符合需求时进入核验；发现源码变化时先判断业务影响，不把每次提交都当作新功能。
4. 按 [验收与完成登记](references/verification.md) 刷新当前源码分析与流程依据，执行真实验收，并对当前定义版本登记完成。
5. 与完成登记一起删除本次已处理且验收通过的批注；保留失败、未明确、未处理及处理期间新增的批注。读回源码状态与 HTML，交付阅读链接、实现结果及必要的剩余事项。

核验业务步骤衔接时读取 [业务流程核验](references/flow-verification.md)，执行扫描、入口映射、场景验证和状态同步。漏读、漏记录及可修正映射继续补齐；真实能力限制才允许明确的部分交付。流程结论与功能完成历史分开保存。

## 必须保留的边界

- 调用本 Skill 不代表授权任意开发；草稿可能只是未核验。仅处理本次授权范围内的明确需求。
- 保存定义、批注或代码变化不会自动启动 AI。只能读取已保存到产品 JSON 的批注，不能声称处理了浏览器中未保存的输入。
- 保留用户原文、稳定编号、备注和验收历史；源码检查不自动重置业务版本或替换旧基线。
- 用 CLI 的哈希、版本和实际执行记录保存；分析或验收失败时不登记完成、不另行删除批注。
