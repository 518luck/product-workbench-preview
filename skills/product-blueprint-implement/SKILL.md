# 实现蓝图中的修改

从现有产品书读取用户在页面保存的定义、草稿及批注，将选定需求实现到代码。保留稳定编号、原始需求和历史，完成后复用核验 Skill 核验本次功能，再同步蓝图。

## 选择范围

先定位目标项目 PROJECT，执行 `workflow plan PROJECT --skill implement --json`。valid:false 时报告配置关闭项或依赖，不执行后续任务、不自动开启 Skill。启用只表示允许当前任务；配置不代替用户授权。实现依赖核验；核验关闭时在修改代码之前结束，不能跳过核验。

先运行 `document status`、`feature list`，查找具体未实现项、已修改定义、已保存批注及相关源码变化。向用户列出待办名称与编号，询问“实现全部待办，还是指定功能？”，提供“全部待办 / 选择功能 / 取消”。待办为空时如实说明，不新增需求凑任务。

用户已经指定编号或明确选择全部时直接沿用；初始化或核验 Skill 的提示不自动构成任意代码开发授权。完成状态但有新批注的功能也属于候选。源码变化可能是重构，先对照定义，不重复实现已有行为。

## 执行

1. 按 [产物目录](references/artifacts.md) 定位原产品书，固定本次选定编号、目标 revision 和批注 id。浏览器未保存的输入无法处理，需求必须先写入产品 JSON。
2. 按 [实现流程](references/workflow.md) 读取相关源码、规则、流程与依赖。明确需求直接实现；有歧义、冲突或需扩大范围时先确认，保留批注。只实现本次选定内容。
3. 刷新受影响源码分析与业务依据；新入口按 [业务发现](references/business-discovery.md) 归属到真实目标。初始化、核验、实现三个协作入口不能替代目标项目的完整功能目录。
4. 调用 `product-blueprint-verify`，传入本次产品书路径、选定功能编号和目标版本，复用 [核验与登记](references/verification.md)。范围已明确，不再次询问单个/全部；执行真实验收并保存逐功能结果。
5. 对实现且核验通过的功能登记验收，与完成批次一起删除本次已处理批注。失败、含歧义、未处理和执行期间新增的批注保留。读回定义、状态、源码基线与 HTML 后交付。

需求由用户在页面修改，本 Skill 不提供单独的需求维护模式，也不接受未保存的口头想法直接当成产品定义。已保存批注的需求整理属于所选实现的一部分，不能未经用户同意改换目标。

## 交付

提供可编辑产品书链接，简短说明本次实现及核验结果。单功能只声明该范围；全部待办不等于整本产品书全部功能已核验。代码已实现但运行受限时保留实现完成判断，明确运行未核验并保留批注，不伪造通过。

所有 CLI、服务和验证操作由 AI 完成，不让用户手输命令。遇到 JSON 已保存而 HTML 更新失败时只恢复渲染，避免重复修改和重复完成登记。
